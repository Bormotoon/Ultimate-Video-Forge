**WhisperSync** синхронизирует звук и видео при **dual-system recording**: камера снимает видео с черновым звуком, а внешний рекордер (петличка, Zoom, Tascam, телефон с радиомикрофоном) пишет чистый звук отдельно. Два устройства работают от независимых кварцевых генераторов, поэтому за минуты и часы записи их время медленно расходится — ползучий, иногда нелинейный **дрейф часов** до секунды, который waveform-матчеры фиксируют в начале, но не умеют отслеживать дальше. WhisperSync находит точное выравнивание *по всей длине записи* и создаёт готовый к импорту **FCPXML**-проект для Final Cut Pro или DaVinci Resolve.

![WhisperSync GUI](docs/images/main_window.png)

> Главное окно: drag-and-drop источников, выбор стратегии, живой многодорожечный таймлайн и лог в реальном времени.

Пайплайн: **транскрипция** → **поиск словесных якорей** → **RANSAC-оценка K/offset** → **стратегия синхронизации** → **рендер синхронного аудио** → **экспорт FCPXML**.

Используя [faster-whisper](https://github.com/SYSTRAN/faster-whisper) (CTranslate2), WhisperSync транскрибирует оба аудиопотока с таймстемпами на уровне слов, находит совпадающие слова (якоря) через последовательностное выравнивание, применяет RANSAC-регрессию для устойчивой оценки коэффициента часов **K** и **смещения**, а затем одной из трёх стратегий пересобирает звук рекордера под картинку. Рендер сохраняет родные каналы и битность рекордера сквозь весь путь (никакого принудительного моно/16 бит) и использует прозрачный ресемплинг вместо time-stretch там, где реальный дрейф часов достаточно мал. Исходные медиафайлы никогда не изменяются.

## Возможности

### Движок синхронизации

- **Якоря на уровне слов** — оба трека транскрибируются с по-словными таймстемпами; общие слова становятся временными якорями. Работает там, где waveform-матчеры сдаются (эхо в камере, дальние микрофоны, шумные помещения).
- **Грубый-затем-точный матчинг для длинных источников** — клип сначала грубо локализуется в многочасовом рекордере голосованием по редким словам, затем точно матчится в узком окне.
- **RANSAC-регрессия + двухступенчатый фильтр выбросов** — устойчивая оценка K и offset, переживающая ошибки транскрипции и ложные совпадения; юникод-нормализация токенов сохраняет якоря на любом языке («ё», тире, кавычки — не помеха).
- **Три честные стратегии** — Global Linear, Local Time-Stretch и рекомендуемая Hybrid (фразы по якорям, паузы поглощают остаток). См. [гид](#гид-по-стратегиям).
- **Auto-strategy** — после каждого прогона характер дрейфа (residual, разброс локальных скоростей) сверяется с использованной стратегией; если лучше подошла бы другая — warning скажет, какая и почему.
- **Акустический fallback («Strategy 0»)** — клип *без единого* текстового совпадения ни с одним рекордером (музыка, шум, язык, который Whisper не берёт, почти-тишина) выравнивается грубым GCC-PHAT сканом по волновым формам, без слов.
- **Boundary Flex** — покадровое доуточнение губ-синка: старт каждого рендер-куска акустически поправляется кросс-корреляцией (GCC-PHAT) звука камеры и рекордера (вкл. по умолчанию).
- **Seam-snap-to-silence** — границы кусков в piecewise-стратегиях притягиваются к ближайшей паузе между словами рекордера, чтобы разрез никогда не попадал внутрь слова (никакого «заикания»).
- **Per-camera калибровка губ-синка** — постоянную задержку «микрофон↔губы», зашитую в аудиотракт конкретной камеры, не видит ни один акустический метод; `camera_av_offset_ms` (глобально или по камерам) её компенсирует.
- **Гейт по числу якорей** — клипу со слишком малым числом якорей не доверяется шаткий таймкод-фит; он укладывается по порядку имён с предупреждением, а не улетает в заведомо неверную позицию.

### Качество звука (bit-perfect рендер)

- **Родные каналы и битность сквозь весь путь** — никакого принудительного моно и 16 бит; стерео 24-бит на входе — стерео 24-бит на выходе. Куски режутся из лоссless PCM-мастера (заодно чинится несэмпло-точный seek в mp3/m4a-источниках).
- **Прозрачный ресемплинг вместо time-stretch** — реальный дрейф часов — доли процента; такие куски конформятся ресемплингом («varispeed», сдвиг питча на единицы центов — неслышимо на речи) вместо `atempo`/WSOLA с его фазовыми артефактами. WSOLA включается только когда куску действительно нужна большая коррекция.
- **Фейды только там, где нужны** — акустически непрерывные куски стыкуются встык; фейд (слышимая «ямка» громкости) ставится только на реально разрывные швы.
- **Сборка одним проходом** — конкатенация, точная длина и опциональный дакинг пауз в одном ffmpeg-энкоде, а не цепочке поколений; `libsoxr`-ресемплинг где доступен.
- **Дакинг пауз (опция)** — приглушает рекордер в паузах, где молчат *обе* дорожки (по полным спискам слов, не по зазорам якорей), скрывая рассинхрон эмбиента между фразами.

### Входы и выходы

- **Мультикамера** — клипы каждой камеры в своей подпапке; каждая камера на своей дорожке таймлайна, чистый звук синхронизируется один раз с камеры-референса (автовыбор или `--audio-source-camera`).
- **Несколько рекордеров** — `--audio-file` несколько раз; `--recorder-mode best` берёт лучший рекордер на клип (одна дорожка), `all` кладёт каждый рекордер на свою (мульти-микрофонные съёмки).
- **Экспорт FCPXML** (по умолчанию v1.9) — ссылки на нетронутые видеофайлы плюс рендеренные синхронные WAV, с честными атрибутами каналов/рейта каждого ассета; файл валидируется перед выдачей.
- **`--render-master-wav`** — дополнительно миксует все синхронные voice-клипы (и эмбиент, если включён) по их позициям в один WAV на весь таймлайн поверх тишины — для тех, кто работает без NLE.
- **Дорожка эмбиента (опция)** — AI-модель разделения источников убирает собственный (эхный, слегка рассинхронный) голос камеры, оставляя атмосферу помещения, на отдельной дорожке; работает в изолированном `.sep-venv`, батчем с одной загрузкой модели.
- **Поиск дублей (опция, `--detect-retakes`)** — находит реплики, переснятые прямо в записи (запинка, стоп, заново), и **ставит маркер** на каждую попытку, чтобы к ним можно было перейти сразу, а не искать запинки вручную. Транскрипт-эвристика, полностью неразрушающая — ничего не вырезается, не сдвигается и не перетаймируется.
- **Перепроверка синка (опция, `--self-check warn|repair`)** — после рендера заново транскрибирует голосовой монолит каждого клипа и сравнивает его слово-в-слово с собственным транскриптом камеры, отмечая участки, где содержание или тайминг расходятся сильнее обычного джиттера Whisper между независимыми прогонами. Ловит дефекты, которые не видит акустическое измерение лага в `--verify` (пропущенное/задвоенное слово, кусок, собранный из не того участка рекордера). `warn` только сообщает находки; `repair` дополнительно переалайнивает и перерендеривает небольшой участок вокруг каждого отмеченного спана, затем проверяет ещё раз. Стоит один дополнительный проход Whisper на клип (два, если хоть один спан потребовал починки).
- **Экспорт транскриптов** — полные транскрипты каждого рекордера и клипа камеры сохраняются как JSON + SRT рядом с выходом (с таймстемпами слов).

### GUI

- **PyQt6-приложение с тёмной темой** и drag-and-drop зонами для папки видео, файла(ов) рекордера и папки вывода.
- **Мульти-рекордер** — бросьте несколько аудиофайлов сразу; при 2+ файлах разблокируется выбор режима `best`/`all`.
- **Живой многодорожечный таймлайн** — по строке на камеру и на аудиодорожку: реальная позиция каждого клипа, применённое изменение скорости (напр. `+0.10%`) и живой статус: pending (пунктир), working (оранжевая рамка), done (залит). Наведение — offset / duration / in-point / speed.
- **Диалог Transcription Settings** — модель, язык, устройство, compute type, режим транскрипции (fast/quality) и initial prompt без правки конфиг-файла.
- **Re-run with Selected Strategy** — после прогона переключите стратегию и запустите заново; транскрипты в кэше, пересинк идёт сразу в выравнивание/рендер.
- **Чекбокс Detect retakes** — находит переснятые дубли реплик и отмечает каждую попытку маркером (см. [Поиск дублей](#поиск-дублей-retakes)); по умолчанию выкл.
- **Выпадающий список Self-check (Off / Warn only / Warn + auto-repair)** — заново транскрибирует каждый рендеренный клип и отмечает участки расхождения содержания/тайминга с собственным транскриптом камеры сверх обычного джиттера Whisper; вариант с починкой дополнительно переалайнивает и перерендеривает каждый отмеченный спан. По умолчанию выкл. (один дополнительный проход Whisper на клип, два — если нужна починка).
- **Выпадающий список Voice enhancement** — опционально чистит рендеренный голос (denoise / denoise+de-reverb / Resemble Enhance / SGMSE+ диффузия / RE-USE) перед тем, как self-check его проверит; плюсы/минусы каждого варианта — во вкладке Help. По умолчанию выкл.
- **Взвешенный общий прогресс** — одна непрерывная шкала на все стадии (без сбросов на каждой), плюс явный статус «Loading Whisper model…» при первой загрузке модели.
- **Предупреждения пайплайна в логе** — невыровненные клипы, высокий residual, совет по стратегии, проблемы валидации.
- **Отзывчивая отмена** — срабатывает посреди клипа, даже во время большого многоядерного рендера.
- **Встроенная вкладка Help** — учебник плюс интерактивный симулятор микро-синхронизации, показывающий, как каждая стратегия перестраивает звук при движении ползунков дрейфа и длины фразы.

### CLI и автоматизация

- **Полный headless-режим** — каждая настройка доступна флагом или JSON-конфигом; `--json` печатает машиночитаемый отчёт в stdout, прогресс — в stderr.
- **Осмысленные коды возврата** — `0` успех, `1` сбой выполнения, `2` ошибка аргументов/конфига.
- **`--dry-run`** — только скан + транскрипция + выравнивание, сводка без обработки звука.
- **`--verify`** — после рендера меряет *реализованный* губ-синк каждого клипа через GCC-PHAT и печатает median/p90/max (доступно и отдельно: `tools/verify_sync.py`).
- **`--self-check warn|repair`** — после рендера заново транскрибирует голосовой монолит каждого клипа и сравнивает его с собственным транскриптом камеры, отмечая (или чиня) участки расхождения содержания/тайминга, которые не видит акустическое измерение `--verify` (см. [Перепроверка синка](#перепроверка-синка-self-check)).
- **`--voice-enhance`** — опционально чистит рендеренный голос (denoise/de-reverb/генеративная/диффузионная модель) перед тем, как self-check его проверит; шесть вариантов на выбор (см. [Улучшение голоса](#улучшение-голоса)).
- **Самопроверка окружения** — `python -m whispersync.engine.system_check`: ffmpeg, CUDA (тем же путём ctranslate2, что и движок), зависимости, место на диске, какие окружения улучшения голоса/эмбиента настроены; пишет `report.json`.

### Производительность и надёжность

- **Ускорение на NVIDIA GPU через ctranslate2** — torch не нужен; батчевый инференс — главный рычаг скорости, с автоматической OOM-лестницей (меньше батч → легче compute type → CPU).
- **Кэш транскрипций** — ключ SHA-256 по файлу, настройкам и *фактическому* (резолвнутому) device/compute type; повторные прогоны пропускают транскрипцию целиком. Опциональный прунинг по возрасту (`cache_max_age_days`).
- **Один общий рендер-пул** — куски всех клипов рендерятся на всех ядрах через единый пул процессов; сборка каждого клипа перекрывается с рендером следующих.
- **Boundary Flex в памяти** — оба трека декодируются в память один раз на клип, окна — слайсы массивов (никаких ffmpeg-спавнов на каждую границу).
- **Изоляция запусков** — у каждого прогона свой уникально названный каталог scratch на выходном томе и кооперативная блокировка выходной папки, поэтому два прогона не могут перезаписать аудио друг друга или удалить чужие рабочие файлы; второй прогон в ту же папку получает понятный отказ вместо тихого смешивания.
- **Атомарная публикация результатов** — FCPXML, мастер-WAV и каждая отрендеренная голосовая дорожка пишутся во временный файл рядом с местом назначения и переносятся на место только целиком, поэтому падение или отмена не оставят обрывок там, где лежал рабочий результат.
- **Гейт приёмки выравнивания** — каждая карта времени проверяется на количество доказательств, покрытие, невязку и физически правдоподобное отношение частот *до* того, как по ней что-то размещается или рендерится; не прошедшая карта становится явно помеченным unresolved-клипом, а не уверенным неправильным рендером.
- **Fork-безопасность** — рендер-пул никогда не форкается (нативные потоки Qt, CTranslate2 и CUDA не видны никакой проверке «я однопоточный?»); используются forkserver/spawn.
- **Ранняя выгрузка VRAM** — модель Whisper выгружается сразу после выравнивания, освобождая GPU для рендера/сепарации.
- **Конфигурация проверяется заранее** — типы, перечисления, диапазоны и конечность чисел проверяются один раз, после слияния CLI/GUI-переопределений и до начала транскрипции; неверное значение — однострочная ошибка использования (код возврата 2), а не странный результат через несколько часов.
- **Кроссплатформенность** — Windows, macOS, Linux; CI на Python 3.10–3.14, плюс отдельная задача, которая ставит собранный wheel в чистое окружение вне checkout и проверяет точки входа, поздние импорты и упакованные ресурсы.

### Вкладка Help с интерактивным симулятором

![Симулятор](docs/images/simulator.png)

Вкладка **Help** — встроенный учебник: подробно описывает весь процесс и содержит интерактивный **симулятор микро-синхронизации**. Двигайте ползунки **дрейфа** и **длины фразы**, переключайте стратегию слева — и смотрите, как дорожка рекордера (красная) перестраивается под картинку (синяя), ровно как в настоящем таймлайне. Показатели точности и индекса искажения делают компромисс «тайм-стретч против пауз» осязаемым ещё до запуска.

## Как это работает

1. **Probe** — читаются длительность и аудиоформат (каналы, битность, sample rate) каждого клипа.
2. **Транскрипция** — Whisper превращает черновой звук камеры и звук рекордера в транскрипты с таймстемпами слов. Многочасовые рекордеры идут через батчевый GPU-инференс; результаты кэшируются.
3. **Поиск якорей** — общие слова обоих транскриптов становятся временными якорями. Сначала грубое голосование по редким словам локализует клип в рекордере, затем точный матчинг в узком окне.
4. **Фит** — RANSAC-регрессия оценивает коэффициент часов **K** и **offset**, отбрасывая ложные совпадения как выбросы (два этапа: грубое окно + пост-фит фильтр по резидуалам).
5. **Пересборка** — выбранная стратегия превращает выравнивание в рендер-«куски» (старт в рекордере, длительность, темп-фактор); seam-snap и Boundary Flex уточняют точки разреза; каждый кусок конформится прозрачным ресемплингом или atempo и собирается в один непрерывный WAV на клип, в родном качестве рекордера.
6. **Экспорт** — пишется FCPXML со ссылками на исходные видео и рендеренный синхронный звук, готовый для Final Cut Pro / DaVinci Resolve.

## Требования

| Компонент | Минимум | Рекомендуется |

- **CUDA/cuDNN** нужны только для GPU-режима — ставятся через [NVIDIA CUDA Toolkit](https://developer.nvidia.com/cuda-toolkit).

## Гид по стратегиям

| Стратегия | Название | Когда использовать |
|-----------|----------|--------------------|
| **1** | Global Linear | Линейный дрейф часов (самый частый случай). Один темп-конформ на весь файл. Быстрее всего, минимум обработки. |
| **2** | Local Time-Stretch | Нелинейный дрейф, «плавающий» темп. Каждый сегмент между якорями со своим коэффициентом; границы притянуты к паузам между словами. |
| **3** | Hybrid (Global + Silence) | Универсальная, **рекомендуемая по умолчанию**. Попредложенчная: рекордер режется ТОЛЬКО в реальных паузах между предложениями (пауза ≥ `phrase_gap_threshold` = конец предложения), каждое предложение конформится одним куском по сглаженной локальной скорости дрейфа (прозрачный ресемплинг — джиттер якорей не попадает в речь), а куски-паузы поглощают весь остаток размещения (растягивание room tone неслышимо). Устойчива к нелинейному дрейфу; разрез никогда не попадает в речь. |

```
Strategy 1        Видео:  |========================>
                  Аудио:  |========================>  × conform(1/K)

Strategy 2        Видео:  |=== сег1 ===|=== сег2 ===|=== сег3 ===>
                  Аудио:  |== сег1 ==>|==== сег2 ====|== сег3 ==>   (свой коэффициент на сегмент)

Strategy 3        Видео:  |== фраза ==| пауза |== фраза ==| пауза |== фраза ==>
                  Аудио:  |==×(1/K)===| тишина|==×(1/K)===| тишина|==×(1/K)==>
```

> **О «тональности».** Реальный дрейф часов — доли процента, и такие куски WhisperSync конформит прозрачным ресемплингом вместо time-stretch: питч сдвигается на ту же крошечную долю (единицы центов, неслышимо на речи) без фазовых артефактов WSOLA. `atempo` включается только когда фактическая коррекция куска превышает порог (`stretch_method` / `RESAMPLE_CONFORM_MAX_DEVIATION`).

> **Заикание на швах.** Стратегия 3 в принципе не может разрезать речь — её границы ОПРЕДЕЛЯЮТСЯ паузами между предложениями. В стратегии 2 границы притягиваются к ближайшей паузе между словами (seam-snap двигает и rec-, и cam-сторону брейкпоинта, чтобы темп-факторы не разъезжались). Boundary Flex двигает границы без повтора или пропуска контента рекордера — его губ-синк-коррекции не могут породить микроповторы.

> **Auto-strategy.** После каждого прогона измеренный характер дрейфа сверяется с использованной стратегией; если другая подошла бы лучше — warning скажет, какая и почему. Пересинк дешёвый — транскрипты в кэше.

> **Strategy 0 (акустический fallback).** Если у клипа нет ни одного пригодного текстового совпадения ни с одним рекордером (музыка, шум, неподдерживаемый язык), грубый GCC-PHAT скан по сетке оценивает offset/K напрямую по волновым формам — менее точно, чем словесные якоря, но полный отказ превращается в рабочее размещение, пока один и тот же физический звук доходит до обоих микрофонов.

> **Размещение клипов.** Каждый клип выравнивается к рекордеру независимо, позиция берётся из совпавших таймкодов — клипы не обязаны идти встык, реальные паузы между дублями сохраняются. Клип с числом якорей ниже `min_anchors` укладывается по порядку имён с предупреждением.

> **Мультикамера.** Клипы каждой камеры — в свою подпапку `--video-dir` (напр. `videos/camA/`, `videos/camB/`). Каждая камера на своей дорожке; чистый звук синхронизируется один раз с камеры-референса (`--audio-source-camera`, автовыбор по лучшему выравниванию), чтобы не задваиваться на углах. Видеофайлы в корне `--video-dir` при наличии подпапок-камер игнорируются с предупреждением.

> **Несколько рекордеров.** `--audio-file` несколько раз. Каждый клип выравнивается ко всем рекордерам; таймлайн строится по «основному» (лучшее покрытие). `--recorder-mode best` (по умолчанию) — одна дорожка, лучший рекордер на клип; `all` — каждый рекордер на своей дорожке (несколько петличек/спикеров). **Важно:** если файлы — просто последовательные куски *одного* устройства (рекордер бьёт запись по 15 мин), у них одни часы — склейте их заранее без потерь (`ffmpeg` concat), а не передавайте как разные рекордеры.

## Поиск дублей (retakes)

Неотредактированная запись лекции или монолога часто полна переснятых на месте реплик: спикер запинается, останавливается и повторяет фразу заново — иногда несколько раз — прежде чем продолжить. `--detect-retakes` (по умолчанию выкл.) находит такие места автоматически и ставит **маркер** на каждую попытку: `Retake N — keep` для той, на которой спикер остановился, и `Retake N — take K` для отброшенных. Сам таймлайн не меняется: маркеры показывают, куда смотреть, а монтаж остаётся за вами.

> **Почему маркеры, а не audition.** Раньше каждая группа экспортировалась как Final Cut *audition*. Это рассинхронизировало результат: audition начинался в начале группы, но играл звук той попытки, которая находится позже в клипе, а изображение вообще не переключалось — дубли [2 с, 4 с] и [5 с, 8 с] давали опережение голоса на 3 с и дыру в чистой дорожке. Настоящий audition должен переключать связанные A/V-диапазоны вместе и перемонтировать окружающий материал — это отдельная функция со своей временной моделью; маркер сообщает ровно ту же находку, ничем не рискуя синхронностью.

```bash
python main.py --cli --video-dir ./videos --audio-file rec.wav --detect-retakes
```

> **Как это работает.** Поиск идёт по собственному транскрипту рекордера (он уже вычислен для синхронизации), на уровне отдельных слов-токенов: ищется короткая последовательность слов, которая дословно повторяется вскоре после первого произнесения — а не только повторы целых предложений, поскольку рестарт обычно возобновляет фразу, а не начинается с чистой границы. Последовательные рестарты одной и той же реплики объединяются в одну группу (2 и более попыток, причём три и более одинаковых дубля попадают в одну группу целиком); ничего не удаляется и не переставляется местами — алгоритм только решает, какие участки отметить.
>
> **Настройка.** `retake_min_words` (по умолчанию 4) — сколько слов должно совпасть, чтобы засчитать рестарт; увеличьте, если короткие частые фразы («что это», «то есть») ложно определяются как дубли. `retake_max_gap_s` (по умолчанию 6.0 с) — максимальная пауза между двумя попытками одной реплики, после которой это считается не дублем, а несвязанным повтором позже по записи.
>
> **Это эвристика, проверяемая неразрушающим способом.** Поиск точных повторов не поймает все дубли-перефразировки и изредка может сгруппировать случайное совпадение фразы, не являющееся настоящим дублем — но поскольку ничего не вырезается, ложное срабатывание — это просто один маркер, который редактор проигнорирует, а пропущенный дубль не хуже, чем если бы фича вообще не запускалась. В планах — LLM-уточнение (по образцу локального llama.cpp-скоринга моментов в [Podcast Reels Forge](https://github.com/Bormotoon/Podcast-Reels-Forge)), которое сможет ловить перефразированные рестарты и определять, какая попытка была лучше по подаче, а не просто «последняя».

## Перепроверка синка (self-check)

`--verify` меряет *реализованный* губ-синк через акустическую кросс-корреляцию — но не видит дефектов СОДЕРЖАНИЯ: пропущенное слово, задвоенная фраза или кусок, отрендеренный не из того участка рекордера, всё равно могут показать небольшой лаг, если достаточная часть окружающего звука совпадает. `--self-check` (по умолчанию выкл.) закрывает этот пробел: после рендера голосового монолита клипа он заново транскрибируется Whisper'ом и сравнивается слово-в-слово с собственным транскриптом клипа камеры (уже вычисленным при выравнивании). Участки, где они расходятся — либо по таймингу сверх обычного джиттера Whisper между независимыми прогонами, либо просто по словам — выводятся. Два режима строятся на одной и той же детекции:

- **`warn`** — только сообщает отмеченные участки для проверки в NLE. Ничего не перерендеривается.
- **`repair`** — дополнительно переалайнивает небольшой участок рекордера вокруг каждого отмеченного спана и перерендеривает только покрывающий его кусок(и), затем проверяет результат ещё раз, прежде чем принять исправление. Участок, который не удалось уверенно переалайнить (или который всё ещё не совпадает после попытки), сообщается точно так же, как находка в режиме `warn` — вместо риска ухудшить результат остальная часть клипа никогда не трогается.

```bash
python main.py --cli --video-dir ./videos --audio-file rec.wav --self-check warn
python main.py --cli --video-dir ./videos --audio-file rec.wav --self-check repair
```

> **Как это работает (детекция).** Рендеренный voice-WAV транскрибируется заново (`self_check_transcribe_mode`, по умолчанию `fast`) и сопоставляется с транскриптом камеры на уровне токенов тем же подходом normalize+difflib, что используется для якорного матчинга. Последовательность из `self_check_min_run_words` (по умолчанию 5) и более совпавших слов подряд, чья медианная тайминг-дельта превышает `self_check_shift_threshold_s` (по умолчанию 0.35 с), помечается как `shifted`; последовательность из `self_check_min_content_words` (по умолчанию 5) и более слов вообще без пары на другой стороне помечается как `content`. Два дискриминатора отсекают шум транскрипции (оба откалиброваны на реальном материале, где измеренный акустический лаг был <25 мс всюду): дельта слова — это *минимум* по его началу и концу (эхо на дорожке камеры «размазывает» атаки слов на 300-500 мс даже при идеальном синке, а настоящий сдвиг двигает оба края), и большая дельта отбрасывается, если то же слово присутствует на стороне камеры в *правильное* время (difflib спарил частое слово или повторённую фразу не с тем дальним вхождением — это не дефект рендера).
>
> **Как это работает (починка).** ffmpeg-рендер детерминирован — повторный рендер ТОГО ЖЕ участка рекордера один-в-один воспроизведёт дефект содержания побитово, поэтому единственное, что чинит и `shifted`, и `content` спан — это заново определить, откуда в рекордере на самом деле берётся этот участок речи. `repair` переалайнивает именно эту окрестность: сначала транскрипт-матчинг, ограниченный отмеченным спаном плюс несколько секунд контекста (тот же normalize+difflib+RANSAC подход, что и для всего клипа, но в узком окне), с откатом на локальную акустическую GCC-PHAT-проверку (как в Boundary Flex / акустическом fallback), когда рядом недостаточно слов для доверия матчингу. Починенный участок перепланируется той же sentence-wise логикой кусков, что и основной рендер, рендерится и вклеивается в существующий монолит — всё за пределами отмеченного спана с запасом остаётся нетронутым побитово.
>
> **Цена.** Это дополнительный полный проход Whisper на каждый рендеренный клип (второй проход, если хоть один спан потребовал попытки починки, чтобы проверить результат). Основной движок транскрипции по-прежнему выгружается перед рендером как обычно (рендер — чистый ffmpeg); self-check затем загружает собственный движок — одна перезагрузка модели, и никогда двух копий модели в VRAM одновременно.

## Улучшение голоса

`--voice-enhance` (по умолчанию выкл.) прогоняет стороннюю модель по каждому рендеренному голосовому монолиту сразу после рендера и **до** self-check — чтобы self-check проверял именно тот звук, который вы в итоге получите. В прослушивающем тесте сравнили шесть вариантов; единого лучшего значения по умолчанию нет — выбор зависит от материала и от того, сколько времени вы готовы потратить на рендер:

| Режим | Что делает | Скорость | Заметки |
|------|---------------|-------|-------|
| `denoise` | Устранение шума Mel-Roformer | Быстро | Тот же стек `.sep-venv`, что и дорожка эмбиента. Самый безопасный выбор — почти не трогает тембр голоса. |
| `denoise_dereverb` | + второй проход, убирающий отражения комнаты | Быстро | Может «пересушить» хвосты согласных или тепло комнаты на некотором материале — сравните на слух перед тем, как выбрать для проекта. |
| `resemble` | Resemble Enhance (генеративная модель) | ~2.5× медленнее реального времени на современной GPU | Может дать студийный тембр, ценой риска тонких генеративных артефактов на сложных местах. **Экспериментально**, и это **моно**-модель — стерео-монолит вернётся продублированным моно. Ставится в то же `.sep-venv`: `.sep-venv/bin/pip install resemble-enhance`. |
| `sgmse_denoise` / `sgmse_dereverb` | Диффузионный денойз/дереверб SGMSE+ | **~в 5 раз медленнее реального времени** | Самый чистый результат из шести, но реалистичен только для коротких клипов — нужно отдельное окружение `.enh-venv`. |
| `reuse` | NVIDIA RE-USE (денойз+дереверб+удаление клиппинга за один проход) | Быстро | Самый сильный результат за один проход, но веса лицензированы как **NSCLv1 (только некоммерческое использование)**, а запускается через Docker с собственным инференс-кодом NVIDIA, который вы предоставляете сами под их лицензией — проект не может его распространять. Укажите `--reuse-source-dir` на папку, куда его клонировали. |

```bash
python main.py --cli --video-dir ./videos --audio-file rec.wav --voice-enhance denoise
python main.py --cli --video-dir ./videos --audio-file rec.wav --voice-enhance denoise_dereverb
```

> **Окружения.** `denoise`/`denoise_dereverb` переиспользуют окружение `.sep-venv`, уже используемое `--ambience-track` (см. `setup_sep_venv.sh`) — если эмбиент уже работает, ставить больше ничего не нужно. `resemble` ставится в то же самое venv (`.sep-venv/bin/pip install resemble-enhance`); его собственный CLI `resemble-enhance` обходится стороной (начиная с torchaudio 2.9 ему нужен TorchCodec даже чтобы прочитать файл), поэтому WhisperSync вызывает его Python-API напрямую и сам читает/пишет файлы. `sgmse_*`/`reuse` требуют окружений, которые этот репозиторий не поставляет (отдельное venv для диффузионных моделей, Docker-образ плюс собственный код NVIDIA для RE-USE), и в этой сборке бэкендов для них ещё нет — в GUI они недоступны для выбора. `python -m whispersync.engine.system_check` сообщает, какие окружения настроены, а недоступный режим теперь сообщается **в начале прогона**, а не в конце: трёхчасовой синк больше не заканчивается сообщением «выбранный режим недоступен».
>
> **Безопасность синка.** Результат каждого варианта приводится (передискретизация/паддинг/обрезка) к точной длительности, частоте дискретизации и числу каналов исходного рендеренного монолита, прежде чем заменить его — это свойство было подтверждено побитовой точностью по всем шести вариантам в исходном прослушивающем тесте, а шаг приведения делает это структурным гарантированным свойством, а не совпадением.

## Выходные файлы

Всё складывается рядом с FCPXML (по умолчанию — в папке видео):

| Путь | Что это |
|------|---------|
| `sync_output.fcpxml` | Файл проекта — импортируйте в Final Cut Pro / DaVinci Resolve |
| `audio_synced/<клип>_voice.wav` | Непрерывный синхронный voice-WAV на каждый клип камеры, в родном качестве рекордера |
| `transcripts/*.json`, `*.srt` | Полные транскрипты всех рекордеров и клипов (с таймстемпами слов) |
| `ambience/<клип>_ambience.wav` | Эмбиент камеры без голоса (только с `--ambience-track`) |
| `sync_output_master.wav` | Единый WAV на весь таймлайн (только с `--render-master-wav`) |

Исходные видео и файлы рекордера никогда не изменяются.

> **`<source-id>`** — короткий идентификатор, выведенный из роли источника,
> папки камеры и имени файла (`cam_camA_DJI_0001`, `rec_take`) и автоматически
> сделанный уникальным. Одних только имён файлов недостаточно: два рекордера
> могут называться `take.wav`, одна камера может содержать `clip.mov` и
> `clip.mp4`, а одинаковые имена клипов у разных камер — обычное дело; в каждом
> из этих случаев артефакт одного источника раньше перезаписывал артефакт
> другого. На отображаемые имена в FCPXML это не влияет.

Пока идёт прогон, в выходной папке также лежат `.whispersync-run.lock` и
каталог `.whispersync-run-<id>/`; оба удаляются по завершении. Оставшаяся от
аварийно завершившегося прогона блокировка перехватывается автоматически.

## Проверка результата

- **`--verify`** — после успешного прогона меряет *реализованный* лаг между каждым рендеренным voice-WAV и звуком камеры через GCC-PHAT кросс-корреляцию, печатая median/p90/max по клипам (и включая цифры в `--json`-отчёт).
- **`--self-check warn|repair`** — заново транскрибирует каждый рендеренный voice-WAV и отмечает (или чинит) расхождения содержания/тайминга с собственным транскриптом камеры — см. [Перепроверка синка](#перепроверка-синка-self-check) для того, что не видит один `--verify`.
- **`tools/verify_sync.py`** — то же измерение как отдельный инструмент для любой пары аудиофайлов: `python -m tools.verify_sync --video camera.mov --voice voice.wav [--json]`. Это тонкая обёртка; само измерение живёт в поставляемом пакете (`whispersync.engine.verify`), поэтому `--verify` работает из установленного wheel, а не только из checkout. Коды возврата: `0` — прошло, `1` — не прошло, `2` — неопределённо или неверные аргументы. «Неопределённо» намеренно не считается успехом: клип, который не удалось измерить, не доказан синхронным.
- **`python -m whispersync.engine.system_check`** — аудит окружения: ffmpeg, CUDA-через-ctranslate2, зависимости, `.sep-venv`, место на диске.

## Troubleshooting

### `CUDA not available, falling back to CPU`

Установите [NVIDIA CUDA Toolkit](https://developer.nvidia.com/cuda-toolkit) и cuDNN, затем запустите `python -m whispersync.engine.system_check` — он проверяет CUDA через ctranslate2, ровно тем путём, которым движок транскрипции пользуется в рантайме (torch не нужен).

### `ffmpeg not found in PATH`

- **Ubuntu/Debian:** `sudo apt install ffmpeg`
- **macOS:** `brew install ffmpeg`
- **Windows:** скачайте с [ffmpeg.org](https://ffmpeg.org/download.html) и добавьте в PATH

### Мало якорей

```
Warning: Only 3 anchors found (minimum: 8)
```

Причины и решения: очень короткий клип (больше речи — лучше), сильный шум (держите `vad_filter` включённым), несовпадающие языки (укажите `--language`), тихий сигнал рекордера (проверьте уровни). Клип ниже `min_anchors` укладывается по порядку имён с предупреждением, а не доверяется шаткому фиту. Если текстовых совпадений нет *вообще* — включается акустический fallback (`acoustic_fallback`, вкл. по умолчанию): волновой GCC-PHAT скан, грубее, но работает на музыке/шуме/тишине, пока один и тот же физический звук доходит до обоих микрофонов.

### Большой residual

```
High residual alignment error: 156.2 ms
```

Дрейф может быть не идеально линейным — попробуйте стратегию 2 или 3 (следите за auto-strategy warning'ом, он назовёт лучший вариант); убедитесь, что якоря покрывают весь клип; попробуйте `large-v3` вместо маленькой модели или `--mode quality` для сложного звука.

### Кэш транскрипций

Кэш живёт в `~/.cache/whispersync/` (на других ОС — платформенный аналог). Ключ учитывает *фактическое* устройство/compute type, поэтому GPU-прогон и прогон с CPU-фолбэком никогда не перепутают кэш. Сброс: `--no-cache` на один прогон, удаление папки или `cache_max_age_days` для автопрунинга.

│   │   └── system_check.py          # Аудит окружения
│   └── gui/

### Поток данных

```
Видеофайлы + файл(ы) рекордера
        │
        ▼
   probe() ──────────────► MediaInfo (в т.ч. каналы / битность аудио)
        │
        ▼
   extract_audio_master() ► лоссless PCM-мастер на рекордер (родные каналы, целевой rate)
        │
        ▼
   WhisperEngine.transcribe() ► Transcript с таймстемпами слов (кэшируется)
        │
        ▼
   matcher.align() ─────► якоря → фильтры выбросов → RANSAC → AlignmentMap (K, offset)
        │                  └─ нет совпадений? → acoustic_coarse_align() (GCC-PHAT fallback)
        ▼
   clip_pieces() ───────► куски (rec_start, duration, factor) с seam-snap-to-silence
        │
        ▼
   refine_piece_boundaries() ► покадровое доуточнение Boundary Flex (опция, вкл. по умолчанию)
        │
        ▼
   общий рендер-пул ────► куски режутся/конформятся параллельно → assemble_continuous()
        │                  (родные каналы/битность, дакинг пауз инлайн)
        ▼
   generate_fcpxml() ───► .fcpxml + audio_synced/*.wav [+ мастер-WAV, эмбиент, транскрипты]
```
